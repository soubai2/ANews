# ANews 桌面新闻 Agent MVP 设计

## 目标

本轮交付一个可运行、可演示、工程结构清晰的 Windows 本地桌面新闻 Agent MVP。应用以 App 内操作为中心，用户可以在桌面端完成新闻接收、阅读、关注、跟进、来源管理、偏好管理和手动刷新。

现有代码由外部模型生成，仅作为概念参考，不作为架构约束。本轮允许受控重写后端领域模型、数据库 schema、服务层、API 层和桌面前端源码。

## 范围

本轮包含：

- Electron + React 桌面端源码结构。
- Python + FastAPI 本地后端服务。
- SQLite 本地数据层。
- 推送页：最新、相关、跟进三个板块。
- App 内新闻详情/阅读视图。
- 来源、偏好、跟进管理页面。
- 关注、跟进、添加来源、启停来源、删除偏好等操作。
- 手动刷新和 2 小时调度骨架。
- 确定性模拟新闻源和可扩展 source adapter 边界。
- 后端自动化测试覆盖核心业务行为。

本轮不包含：

- 依赖互联网的完整真实新闻抓取质量保证。
- 外部模型摘要、实体识别或向量检索。
- 多用户服务端部署。
- 完整 Windows 安装包签名和发布流程。

## 架构

项目采用本地桌面 App + 本地 API 服务的结构。

- `desktop`：Electron + React 桌面端，负责 UI、桌面通知、App 内阅读和本地后端连接。
- `src/anews_agent/domain`：领域模型，例如新闻、来源、偏好、跟进事件、推送结果。
- `src/anews_agent/storage`：SQLite schema、repository、查询和事务。
- `src/anews_agent/services`：推送编排、评分、来源管理、偏好管理、跟进管理、调度。
- `src/anews_agent/api`：FastAPI app、路由、DTO 和错误响应。
- `src/anews_agent/sources`：模拟源和真实来源 adapter 接口。

后端服务是业务真相来源。前端不复制复杂业务规则，只通过 API 读取和提交操作。

## 桌面体验

应用启动后直接进入推送页。界面基调应安静、专业、信息密度适中，优先像工作工具，不像营销页面。

左侧固定导航：

- 推送
- 对话
- 来源
- 偏好
- 跟进
- 设置

顶部状态区显示：

- 最近推送时间。
- 下一次自动刷新时间。
- 手动刷新按钮。
- 后端连接状态。

推送页包含：

- 最新：本轮新增新闻，默认按发布时间倒序。
- 相关：按重要性评分排序，显示推荐原因。
- 跟进：用户跟进事件的实质更新。

新闻卡片展示：

- 标题。
- 来源。
- 发布时间。
- 摘要。
- 分类和标签。
- 重要性标记。
- 推荐原因。
- 关注、跟进、打开操作。

点击新闻后进入 App 内详情页。详情页保留返回和主导航能力。MVP 中可优先展示本地摘要、元数据和来源 URL；如果原网页容器不可用，显示 App 内错误状态和重试操作，不创建独立浏览器窗口。

对话页作为 Agent 控制台，不以大模型聊天为前置依赖。MVP 支持有限命令解析，例如查询新闻、添加来源、查看推荐原因，并把结果映射到本地操作或查询结果。

## 后端 API

FastAPI 提供本地 HTTP API：

- `GET /api/health`：返回服务状态。
- `GET /api/push`：返回当前推送页数据。
- `POST /api/push/run`：立即执行一轮推送。
- `GET /api/news`：按日期、来源、主题、关键词查询新闻池。
- `GET /api/news/{news_id}`：获取新闻详情。
- `POST /api/news/{news_id}/focus`：关注新闻并写入偏好。
- `POST /api/news/{news_id}/follow`：创建跟进事件。
- `GET /api/preferences`：列出偏好。
- `POST /api/preferences`：新增偏好。
- `DELETE /api/preferences/{preference_id}`：删除偏好。
- `GET /api/sources`：列出来源。
- `POST /api/sources`：新增来源。
- `PATCH /api/sources/{source_id}`：启停或更新来源。
- `DELETE /api/sources/{source_id}`：删除来源。
- `GET /api/follows`：列出跟进事件。
- `DELETE /api/follows/{follow_id}`：取消跟进。

API 返回结构应稳定，包含前端展示所需的推荐原因、状态、错误信息和时间字段。

## 数据模型

SQLite schema 重新设计，不要求兼容现有 `anews.db`。

核心表：

- `news_items`：新闻唯一 ID、标题、URL、来源、发布时间、抓取时间、摘要、标签、实体、分类、重要性分数、推荐原因、是否已推送。
- `sources`：来源名称、URL、类型、是否用户指定、是否启用、最近成功时间、最近失败时间、失败原因。
- `preferences`：偏好类型、值、权重、创建来源、创建时间、更新时间。
- `followed_stories`：原新闻、标题、关键词、实体、状态、创建时间、更新时间。
- `follow_updates`：跟进事件、关联新闻、变化摘要、创建时间。
- `push_runs`：推送开始时间、结束时间、窗口开始、窗口结束、状态、错误信息。
- `user_actions`：阅读、关注、跟进、忽略等行为记录。

新闻池按用户本地日期归档查询。去重使用 URL、来源、标题、发布时间和摘要指纹共同判断。不同来源报道同一事件时，MVP 先通过标题和实体相似度建立弱合并，后续可扩展为更强的事件聚类。

## 推送流程

每轮推送执行：

1. 读取 `last_push_at`、用户偏好、跟进列表和启用来源。
2. 计算抓取窗口：`last_push_at - 10 分钟` 到 `now + 10 分钟`；首次运行默认回看 2 小时。
3. 调用默认模拟源和用户来源 adapter。
4. 标准化新闻数据。
5. 去重并写入当天新闻池。
6. 根据偏好、来源权威性、用户指定来源、主流热度、新颖性、时效性和跟进价值评分。
7. 生成最新、相关、跟进板块。
8. 记录推送运行状态。
9. 仅在推送成功后推进 `last_push_at`。

如果某轮失败，不推进 `last_push_at`。用户手动刷新复用同一套流程。

## 来源策略

MVP 使用两类来源：

- 默认模拟源：提供确定性样例新闻，保证无网络环境也能演示完整产品。
- 用户指定来源：保存 URL、类型和状态；每轮推送必须尝试 adapter；失败时记录原因和最近成功时间。

真实 RSS、网页解析和搜索索引作为 adapter 扩展点。后续接入真实抓取时，不改变推送页和 API 合约。

## AI 策略

MVP 不调用外部模型，避免首轮产品体验依赖 API key、网络质量或模型成本。

后续需要摘要、主题提取、实体识别、重要性解释或对话理解时，使用可配置的 AI provider 接口。产品默认倾向 DeepSeek，不默认使用 GPT 或 OpenAI。provider 边界应放在服务层之外，避免模型供应商选择污染新闻入库、推送排序和前端 API 合约。

如果未来用户显式配置其他模型供应商，系统应通过设置页选择 provider、模型名和凭据，而不是在代码中硬编码单一供应商。

## 关注与跟进

关注新闻时，系统提取新闻主题、分类、来源、实体和关键词，写入或增强偏好权重，并记录触发来源。后续相关板块排序立即受影响。

跟进新闻时，系统创建跟进事件，保存原新闻、核心实体、关键词和时间线。每轮推送检查新增报道是否有实质变化。MVP 可先通过关键词和实体匹配生成跟进更新，避免展示无新增信息的重复转载。

## 错误处理

后端错误返回统一结构：

- `code`：稳定错误码。
- `message`：用户可读说明。
- `details`：调试信息，前端按需展示。

关键失败处理：

- 后端不可达：前端显示连接异常和重试。
- 来源抓取失败：记录失败状态，不影响其他来源。
- 推送失败：不推进 `last_push_at`。
- 新闻详情不可打开：留在 App 内显示错误和重试。
- 数据库错误：返回明确 API 错误并记录运行状态。

## 测试策略

后端使用 pytest 做测试先行。重点覆盖：

- 数据模型和序列化。
- SQLite repository。
- 抓取窗口和 10 分钟容错。
- 推送失败不推进 `last_push_at`。
- 去重和新闻池查询。
- 重要性评分。
- 关注写入偏好并增强权重。
- 跟进事件创建和更新生成。
- 来源失败记录。
- FastAPI 核心接口。

前端至少提供构建验证。复杂交互优先保持组件边界清晰，后续可补 React 测试。

## 交付标准

本轮完成时应满足：

- 可以启动本地后端。
- 可以启动 Electron/React 桌面端。
- 推送页能展示最新、相关、跟进板块。
- 用户可以手动刷新新闻。
- 用户可以关注新闻并看到偏好变化。
- 用户可以跟进新闻并看到跟进列表变化。
- 用户可以添加、启停、删除来源。
- 用户可以查看和删除偏好。
- 用户可以在 App 内打开新闻详情。
- 后端测试通过。
- 前端构建通过。

## 设计自检

无未决空白项。本设计明确选择产品级本地 MVP，避免把真实抓取、外部模型摘要和发布安装包混入首轮交付。现有代码被视为可替换参考，因此重写 schema 和分层不会与既有实现冲突。
